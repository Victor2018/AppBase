# TAPD Bug 修复助手

## 概述

使用 TAPD MCP 工具自动获取 bug 详情，分析根因，给出修复方案并实施代码修改。

## 必需工具

本 skill 依赖以下 TAPD MCP 工具（已配置即可用）：
- `mcp__tapd_mcp__tapd_list_workspaces` - 获取项目列表
- `mcp__tapd_mcp__tapd_get_bugs` - 获取 bug 详情
- `mcp__tapd_mcp__tapd_list_bugs` - 搜索 bug（可选）

## 工作流程

### 步骤 1: 解析 Bug 链接

从用户提供的链接提取信息：

**格式 A**: `https://www.tapd.cn/tapd_fe/{workspace_id}/bug/detail/{bug_id}`
- 直接提取 workspace_id 和 bug_id

**格式 B**: `https://www.tapd.cn/tapd_fe/my/work?dialog_preview_id=bug_{bug_id}`
- 提取 bug_id，workspace_id 需查询

**格式 C**: 仅提供 bug_id（如 `1160353330001025967`）
- 需查询 workspace_id

### 步骤 2: 获取 Workspace ID

如果链接中无 workspace_id，调用：

```
mcp_call("mcp__tapd_mcp__tapd_list_workspaces", {})
```

从返回结果中选择对应项目 ID。

### 步骤 3: 获取 Bug 详情

调用：

```
mcp_call("mcp__tapd_mcp__tapd_get_bugs", {
  "bug_ids": ["{bug_id}"],
  "workspace_id": "{workspace_id}"
})
```

获取内容包括：
- 标题、状态、优先级
- 描述（操作步骤、目前结果、期望结果）
- 评论与流转记录
- 接口信息（URL、响应数据）
- 附件/截图/视频链接

### 步骤 4: 分析 Bug 根因

**信息优先级**（从高到低）：

1. **评论中的技术讨论** ⭐ 最高优先级
   - 开发/测试的实际排查结论
   - 接口调试结果、数据验证
   - 问题定位和修复建议

2. **接口信息**
   - 请求 URL、参数、响应数据
   - 错误码、异常堆栈

3. **附件/截图/视频**
   - 视觉证据、复现录屏

4. **描述中的操作步骤**
   - 复现路径（可能不完整或不准确）

5. **目前结果 vs 期望结果**
   - 差异点（以评论结论为准）

**重要原则**：
- Bug 描述可能不准确或过时，**优先以评论中的技术结论为准**
- 评论中开发/测试的排查结论通常最接近根因
- 如果描述与评论矛盾，以评论为准

**常见根因分类**：

| 类型 | 特征 | 修复方向 |
|------|------|----------|
| 接口参数缺失 | 返回"缺少必要参数" | 客户端补充参数或增加前置校验 |
| 状态判断缺失 | 未开通/未完成流程可进入页面 | 增加状态检查，显示缺省页或引导 |
| 数据为空未处理 | 接口返回 null/空数组 | 增加空数据兜底 UI |
| 逻辑顺序错误 | A 未完成可执行 B | 增加流程依赖校验 |
| 服务端问题 | 接口返回 500 或数据异常 | 标记为服务端 bug，客户端增加容错 |

### 步骤 5: 给出修复方案

输出格式：

```markdown
## Bug 分析

**根因**：[一句话说明根本原因]

**影响范围**：[哪些页面/功能受影响]

**评论关键信息**（优先参考）：
| 评论人 | 结论 |
|--------|------|
| [姓名] | [关键结论] |

**描述与评论对比**：
- 描述：[描述中的问题]
- 评论：[评论中的实际结论]
- 结论：[以哪个为准及原因]

## 修复方案

### 方案概述
[整体修复思路]

### 具体改动
1. [文件/模块] - [改动内容]
2. [文件/模块] - [改动内容]

### 验证要点
- [ ] [验证场景 1]
- [ ] [验证场景 2]
```

### 步骤 6: 实施代码修复

1. **定位文件**：使用 `SearchWorkspace` 或 `Glob` 搜索相关文件
   - 搜索关键词：页面名称、功能模块、接口名
   - 示例：搜索 "Wallet"、"BankCard"、"getBankCard"

2. **阅读代码**：使用 `Read` 查看相关代码逻辑

3. **修改代码**：使用 `Edit` 实施修复
   - 遵循项目现有代码风格
   - 新增控件 ID、字符串、Drawable 或类时，按 `android-naming` skill 的规则命名；未安装时以工程内同类文件的写法为准
   - 保持与现有架构一致（MVVM/MVP 等）

4. **文案修改全面检查** ⭐（涉及界面文案时必做）：

   **检查清单**：
   - [ ] **XML 布局文件** - 搜索相关布局文件中的硬编码文案
   - [ ] **strings.xml 资源文件** - 检查字符串资源定义
   - [ ] **代码中的硬编码** - 搜索 Kotlin/Java 文件中的字符串字面量
   - [ ] **多语言文件** - 如有多语言支持，检查 values-en 等目录
   - [ ] **关联页面** - 检查是否有其他页面引用相同文案

   **搜索方法**：
   ```bash
   # 搜索文案关键词（如"必传未上传"）
   Grep: "必传未上传"
   
   # 搜索相关 strings.xml
   Glob: **/strings.xml
   Grep: "必传" 或相关关键词
   
   # 搜索布局文件
   Glob: **/*activity*.xml, **/*fragment*.xml
   ```

   **修改原则**：
   - 优先修改 strings.xml 资源文件，而非硬编码
   - 确保所有引用该文案的地方同步修改
   - 检查是否有代码中动态拼接的文案

5. **验证修改**：检查是否有编译错误或逻辑问题

## 错误处理

### TAPD MCP 工具不可用

如果调用 TAPD MCP 工具失败，提示用户：
1. 检查是否已配置 TAPD MCP 服务
2. 或请用户手动提供 bug 详情（复制粘贴）

### Bug ID 或 Workspace ID 无效

如果获取 bug 失败：
1. 确认 ID 格式正确
2. 调用 `tapd_list_workspaces` 确认项目 ID
3. 调用 `tapd_list_bugs` 搜索 bug

### 代码文件未找到

如果在项目中找不到相关文件：
1. 询问用户项目根目录路径
2. 使用更宽泛的搜索关键词
3. 请用户提供相关文件名或路径

## 注意事项

- **评论优先原则** ⭐：Bug 描述可能不准确或过时，优先以评论中开发/测试的技术结论为准
- **文案修改全面性** ⭐：涉及界面文案修改时，必须检查 XML 布局、strings.xml、代码硬编码、多语言文件，确保无遗漏
- **区分客户端/服务端问题**：根据接口响应判断问题归属
- **遵循项目规范**：修复时保持与现有代码风格、架构模式一致
- **最小改动原则**：只修改必要的代码，不要过度重构
- **验证修复方案**：如果评论中有明确的修复建议，优先采用
